# Візуальне дослідження «Бункер: Протокол»

## Висновок

Проєкту не потрібна ще одна декоративна оболонка поверх нинішніх карток. Найсильніший напрям — перетворити поле на **живий стіл із досьє**, де композиція змінюється разом із фазою гри:

- сценарій і головна дія завжди залишаються у фокусі;
- поточний гравець стає головним об’єктом під час відкриття;
- під час дискусії поле допомагає порівнювати вже відомі факти;
- під час голосування досьє перетворюються на короткі бюлетені;
- атмосфера створюється ілюстраціями, матеріалами й світлом, а не великою кількістю ефектів.

Рекомендована назва нового основного вигляду: **«Живе досьє»**. Класичний і Тактичний режими можна залишити як альтернативи.

## Що показують схожі ігрові платформи

### Board Game Arena

- Головна дія повинна бути в центрі панелі команд.
- Другорядні й недоступні дії не мають конкурувати з нею.
- Панель гравця має з першого погляду показувати особу, порядок ходу й ключові ресурси.
- На мобільному панелі гравців мають займати мінімум місця.
- Часто потрібні елементи розміщуються вище, рідко потрібні — нижче.

Для «Бункера» це означає: одна панель дії, компактна інформація про фазу, пріоритет поточного гравця та різні форми карток для різних фаз.

Джерело: [Board Game Arena — UX Guidelines](https://en.doc.boardgamearena.com/images/5/57/Guidelines_UX_new_compressed.pdf)

### Codenames Online

Сильна сторона — майже повна відсутність декоративного шуму. У центрі залишається сама механіка: сітка карток, команда, поточний хід і одна основна дія. Колір використовується як стан, а не як прикраса.

Для «Бункера» це означає: зелений, червоний, бурштиновий і блакитний мають позначати конкретні ігрові стани; не варто одночасно підсвічувати все поле.

Джерело: [офіційний Codenames Online](https://ftp.codenamesgame.com/)

### Tabletopia

Tabletopia створює атмосферу через знайому модель реального столу: центральна зона, місця гравців, послідовний порядок, матеріали карток і локальні ілюстрації. Інтерфейс залишається однаковим, а візуальність належить самій грі.

Для «Бункера» це означає: досьє повинні виглядати як об’єкти світу гри — папки, печатки, маркери доступу, фотокартки й службові нотатки — але читатися як сучасний інтерфейс.

Джерела: [Inside Tabletopia](https://tabletopia.com/news/inside_tabletopia), [Tabletopia Usability Guide](https://help.tabletopia.com/knowledge-base/usability-guide-for-creating-games-on-tabletopia/)

## Чому нинішній дизайн відчувається слабшим

1. Майже всі блоки мають однакову темну скляну поверхню, тому немає чіткої візуальної ієрархії.
2. Багато блакитних рамок і світіння роблять інформацію рівнозначною.
3. Картка гравця схожа на системну таблицю, а не на персонажа або досьє.
4. Фаза гри змінює колір верхньої панелі, але недостатньо змінює саме поле.
5. Великий фоновий малюнок працює як шпалери й майже не підтримує конкретні дії.
6. Постійні тіні, розмиття та пульсації додають навантаження, але не додають достатньо змісту.

## Рекомендована артдирекція: «Живе досьє»

### Палітра

- Основа: графіт `#0B1014` і темний синьо-сірий `#111C24`.
- Досьє: теплий сіро-паперовий `#C8C1AE` або його темна інверсія для нічного режиму.
- Інформація: холодний блакитний `#61C5E8`.
- Підтвердження й відкриті факти: зелений `#71D6A2`.
- Очікування й ризик: бурштиновий `#E1A95F`.
- Голосування й виключення: червоний `#D96666`.

Ключова зміна: блакитний перестає бути рамкою для всього й використовується тільки для інформаційних та інтерактивних елементів.

### Типографіка

- Залишити **Manrope** для довгого тексту й характеристик: він добре читається українською.
- Замінити Oswald у великих заголовках на **Unbounded** у двох насиченнях — тільки для логотипа, назви фази та великих номерів.
- Значення характеристик робити більшими за їхні підписи, а не однакового візуального рівня.
- Не використовувати капслок для речень; залишити його лише для коротких службових міток.

### Розміщення

#### Відкриття характеристик

- Ліворуч або у верхньому центрі — велике досьє поточного гравця.
- Праворуч — компактна черга інших гравців.
- Кнопка «Передати хід» закріплена в одній панелі дії.
- Умови виживання згорнуті в короткий триптих.

#### Дискусія

- Усі картки вирівняні за відкритими характеристиками.
- Закриті рядки зменшені до одного лічильника.
- Можна тимчасово закріпити 2–3 досьє для порівняння без модального вікна.

#### Голосування

- Замість повних досьє — бюлетені з іменем, 2–4 ключовими відкритими фактами, статусами та активною картою.
- Голосування має одну чітку червону дію.
- Підсумок голосів розташований у самій панелі фази.

### Фонові зображення

Додавати більше повноекранних фонів не рекомендовано. Краще використати зображення локально:

1. один широкий арт катастрофи у верхній зоні сценарію;
2. три узгоджені ілюстрації для катастрофи, бункера й поверхні;
3. невеликі портретні або силуетні фрагменти для досьє гравців;
4. службові штампи й текстури матеріалу як CSS або дуже маленькі повторювані ресурси.

Поточні AVIF-файли вже компактні — приблизно 48–64 КБ кожен. Отже, головна проблема нинішнього поля не в обсязі завантаження, а в повторному промальовуванні великого закріпленого фону та всіх карток під час прокручування.

Для статичних ілюстрацій AVIF доречний: він зазвичай дає менший файл за JPEG/WebP за схожої якості. Але формат не зменшує вартість кожного повторного промальовування великого фону. Тому AVIF потрібно поєднувати з правильним розміром, WebP-резервом і відсутністю `background-attachment: fixed`.

Джерела: [web.dev — AVIF](https://web.dev/learn/images/avif), [web.dev — image performance](https://web.dev/learn/performance/image-performance)

### Анімації

Рекомендовано:

- відкриття характеристики: переворот або розкриття 280–360 мс;
- зміна ходу: короткий рух світлового маркера 220–300 мс;
- голос: ефект службової печатки 250–320 мс;
- виключення: приглушення кольору й поява штампа без тривалого ефекту;
- перехід між фазами: зміна композиції через `transform` та `opacity`.

Не рекомендовано:

- анімований повноекранний AVIF;
- паралакс під час прокручування;
- постійне пульсування багатьох карток;
- анімація тіней, розмиття, висоти або ширини;
- декоративні частинки поверх усього поля.

Для плавності анімації мають змінювати переважно `transform` і `opacity`; властивості, що запускають розкладку або повторне малювання, помітно дорожчі.

Джерело: [web.dev — Animations and performance](https://web.dev/articles/animations-and-performance)

## Продуктивність: обов’язковий бюджет

- Жодних фіксованих повноекранних фонів.
- Жодного `backdrop-filter` на елементах, які рухаються або закріплені під час прокручування.
- Невидимі досьє використовують `content-visibility: auto`.
- Підказки рендеряться окремим верхнім шаром, а не змушують усі картки втрачати ізоляцію.
- Одночасно працює максимум одна атмосферна анімація.
- Анімації поважають `prefers-reduced-motion`.
- AVIF має WebP-резерв; мобільні пристрої не завантажують надмірно великі фони.

Джерела: [MDN — content-visibility](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/content-visibility), [MDN — CSS performance](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Performance/CSS), [web.dev — backdrop-filter](https://web.dev/articles/backdrop-filter)

## Запропонований порядок реалізації

1. **Фундамент:** палітра, типографіка, поверхні без зайвого скла та світіння.
2. **Фазові композиції:** окреме розміщення для відкриття, дискусії й голосування.
3. **Досьє персонажа:** нова картка з виразною ієрархією та службовими матеріалами.
4. **Локальні ілюстрації:** оновлений триптих сценарію у AVIF/WebP.
5. **Мікроанімації:** відкриття, передача ходу, голос і виключення.
6. **Перевірка продуктивності:** плавне прокручування на слабших телефонах і ноутбуках.

## Що варто реалізувати наступним

Рекомендований пакет **«Живе досьє»**:

- нова палітра й Unbounded для акцентних заголовків;
- велика картка поточного гравця;
- компактна черга решти;
- фазове компонування дискусії та голосування;
- оновлений сценарний триптих;
- чотири короткі змістовні анімації;
- без нових повноекранних фонів і без анімованого AVIF.
